# 01-Anatomy：智能体的静态解剖与数据骨架

## 🎯 目录定调 (Purpose)

本目录的核心目的是**“静态解剖”**。
在研究智能体跑起来之前的“运行时 (Runtime)”之前，我们必须先看透它的**静态数据结构**和**底层骨架**。OpenCode 在系统架构中，将所有的对话、权限、工具注册和沙箱规则，都抽象成了强类型的 `zod` Schema 和基于 `Effect-TS` 的不可变状态机栈。

如果你想在这个目录底下继续深挖代码并添加文档，方向应该是：**任何描述“它是什么样子”、“数据怎么存”、“权限在哪标”的静态事物，都放在这里。**

## 📖 核心收录范围与挖掘方向

系统后续的深挖，应该随时对应着 OpenCode `packages/opencode/src/` 中的核心抽象定义：

1. **Agent 的身份证：`Agent.Info` 与 `Permission.Ruleset`**
   - 挖掘方向：它是如何在 `agent.ts` 里声明自己的沙箱深度的？读写权限是如何映射到 OS 路径层面的？
2. **大模型的神脑图谱：`MessageV2` 及其图谱化演进**
   - 挖掘方向：传统对话只有 `role` 和 `content`。OpenCode 的 Message 是一棵树！去探究 `MessageV2` 里的 `TextPart` / `ToolCallPart` / `ToolResultPart` 到底是怎么组装的。
3. **兵器库的注册表：`Tool.Registry`**
   - 挖掘方向：不是指具体的工具实现（比如具体的 bash_tool），而是指工具的动态载入机制。去代码库挖一挖 `tool/registry.ts` 和 `plugin.ts`，看看插件化的工具是如何被抽象成标准的。
4. **状态机模型：`InstanceState`**
   - 挖掘方向：解析为了保证跨平台的健壮性，它如何使用 `effect` 原生库构建一个永远不丢失状态量的上下文环境。
