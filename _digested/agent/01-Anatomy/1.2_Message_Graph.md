# 1.2 Message 处理与图谱化 (Message Graph)

不要把大模型 API（例如 OpenAI API）简单的数组 `[{"role":"user", "content":"..."}, {"role":"assistant"}]` 理解为 OpenCode 处理消息的唯一形态。
在 `packages/opencode/src/session/message-v2.ts` 中，OpenCode 使用了一套有着复杂树状关联和流式生命周期的 **持久化 MessageV2 模型**。它们不仅仅是对话本，更是执行引擎执行每一步操作的快照 (Snapshots)。

## 🔬 数据结构解密：MessageV2

OpenCode 摒弃了纯文本累加，而是设计了 `Info` 和 `Part` 的分离。这种立体结构（立体拓扑/ Graph）使得上下文截断、恢复（Revert）、和打点计费变得可能。

### 消息主干：`MessageV2.Info`
每一条发出的和收到的消息底座，不仅有角色，还绑死了它的上下文元数据：

```typescript
export const Info = z.object({
  id: MessageID.zod,       // 单调递增的严格排序ID
  parentID: MessageID.zod.optional(), // 定义了消息图的层级分叉！非常关键。
  role: z.enum(["user", "assistant"]),
  sessionID: SessionID.zod,
  model: z.object({
    modelID: ModelID.zod,
    providerID: ProviderID.zod,
  }),
  finish: z.string().optional(), // LLM 的退出状态 (eg: "stop", "tool-calls")
  tokens: Tokens.zod.optional(), // 单节点的 Token 消耗截点
  error: z.record(z.string(), z.any()).optional(), // 如果当前节点挂了，记录报错
  summary: z.boolean().optional(), // 💡 灵魂字段！标注此消息是否是被压缩过的“残页”
})
```

### 碎片部件：`MessageV2.Part`
无论是 User 送进来的长文档图片，还是 Assistant 发出的 Tool Call，统统被解构成了一系列的 `Parts`。

```typescript
export const Part = z.discriminatedUnion("type", [
  TextPart,         // 纯文本
  FilePart,         // 文件和图片 (可以保存 base64 也可以外部化存储)
  ToolCallPart,     // Assistant 要求执行的工具
  ToolResultPart,   // 执行结果的返回槽位
  AgentPart,        // Subagent 的触发标记
  CompactionPart,   // [核心] 要求执行上下文洗版的标记
  SubtaskPart       // [流转] 下发子任务流转标记
])
```

## 🧠 这些数据去哪儿了？(State Persistence)

当你和普通的 Web AI 聊天时，刷新页面可能就没了。但在 OpenCode 中，所有这些 `Info` 和相关的 `Part`，都会立刻通过 SQLite（位于 `packages/opencode/src/session/session.sql.ts` 等存储层）落地保存。

这不仅是“历史聊天记录”，它更是整个系统的状态恢复锚点（Save Points）：
- **Revert (时光倒流)**：因为每条消息都有 `id` 和关联的 `parentID` 及对应的 `token` 树，系统可以干净利落地在用户点击 "Ctrl/Cmd + Z" 时砍掉图谱特定分支后的所有结果（见 `SessionRevert` 逻辑）。
- **Synthetic Parts (人造触角)**：对于 MCP 抓取的数据、报错的系统栈，系统会自动为其追加 `synthetic: true` 的 `TextPart`。这使得大模型能读到内部的脏活累活数据，而对于最终呈现给用户的 UI 界面而言，这些部分可以被折叠/抹除。

## 💡 Harness 设计启示：精准外科手术

基于 `MessageV2` 这种颗粒度的数据形态。**做 Harness 就是在做修剪和注射手术：**

如果在极长的 Session 中，你想动态给大语言模型喂入“内部架构规约”（哪怕是一个 1000 行的规范 PDF）。你绝不需要修改原始代码把这个字符串粘上去。
你可以构建一个 Hook，在装配 (Assembly) 发往大模型的最终 JSON Array 时，动态挂载一个携带业务规范数据的隐性 `TextPart(synthetic: true)` 即可。

模型看它，如身临其境；用户看 UI，一无所知。这便是立体化 Message 的魅力所在。
