# 1.2 Message 图谱：`Info + Part` 的会话数据模型

## 源码是什么 (Source)
- `packages/opencode/src/session/message-v2.ts`
- 协同源码：
  - `packages/opencode/src/session/session.sql.ts`
- 关键符号：
  - `MessageV2.Info`
  - `MessageV2.Part`（`text/file/tool/reasoning/compaction/subtask/...`）
  - `toModelMessages(...)`
  - `filterCompacted(...)`

## 解读是什么 (Interpretation)
OpenCode 的消息不是扁平聊天数组，而是“消息节点 + 部件流”的图结构。

1. `Info` 负责会话骨架
- 持有 `role/sessionID/parentID/model/tokens/finish/error` 等上下文元数据。

2. `Part` 负责执行细节
- 文本、附件、工具状态、步骤边界、压缩标记都落在 parts。
- 这使工具执行与对话文本共享同一可追踪数据平面。

3. `toModelMessages` 是协议适配器
- 会把内部 parts 转成模型可消费格式。
- 同时处理 media、tool result 闭环、跨 provider 兼容细节。

4. `filterCompacted` 负责历史截断边界
- 命中完成的 summary 边界后停止向前回溯，避免把旧历史全部塞回上下文。

## implication 是什么 (Harness Implication)
- 你应把会话看成“事件图”，而不是“字符串日志”。
- 做审计/回放/恢复时，优先操作 part 级数据而非整段文本。
- 新能力接入时，最稳入口是新增 part 语义并补适配器。
