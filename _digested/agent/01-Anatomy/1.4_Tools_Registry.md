# 1.4 工具注册表：内建工具与外部工具统一编目

## 源码是什么 (Source)
- `packages/opencode/src/tool/registry.ts`
- 协同源码：
  - `packages/opencode/src/session/prompt.ts`（`resolveTools`）
  - `packages/opencode/src/tool/tool.ts`
- 关键符号：
  - `ToolRegistry.state`（`custom`）
  - `Glob.scanSync("{tool,tools}/*.{js,ts}")`
  - `fromPlugin(...)`
  - `tools(model, agent?)`

## 解读是什么 (Interpretation)
注册表把“内建工具 + 插件工具 + 本地脚本工具”收敛成同一接口。

1. 外部工具自动发现
- 扫描工作目录 `tool/tools`，动态 import。
- 也会加载插件系统暴露的 `tool` 定义。

2. 外部工具会被包装成标准 Tool
- 参数变成 zod object。
- 执行输出统一经过截断处理并产出标准 metadata。

3. 运行时会按模型能力做工具裁剪
- 某些 provider/model 组合会切换 `apply_patch` 与 `edit/write` 可用性。
- 特定工具（如 `codesearch/websearch`）也按 provider 条件启用。

4. 工具定义可再经过 plugin hook
- `tool.definition` 可对描述与参数做二次改写。

## implication 是什么 (Harness Implication)
- 注册表是“可扩展工具平面”的单入口，适合做治理与审计。
- 新工具优先走注册表接入，避免散落在 prompt 组装路径中。
- 通过模型感知裁剪，能减少无效 tool-call 与兼容性报错。
