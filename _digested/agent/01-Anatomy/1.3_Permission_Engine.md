# 1.3 权限引擎：`ask/deny/allow` 的执行闸门

## 源码是什么 (Source)
- `packages/opencode/src/permission/index.ts`
- 协同源码：
  - `packages/opencode/src/permission/evaluate.ts`
- 关键符号：
  - `Permission.ask(...)`
  - `Deferred.make/await`
  - `Permission.reply(...)`
  - `Permission.Event.Asked/Replied`
  - `DeniedError/RejectedError/CorrectedError`

## 解读是什么 (Interpretation)
权限系统的核心是“阻塞执行直到审批完成”。

1. ask 阶段先做规则判定
- 对每个 pattern 计算最终 action。
- 命中 `deny` 立即失败；全 `allow` 直接放行；否则进入 ask。

2. ask 用 Deferred 挂起当前工具链
- 请求进入 `pending` map，并发布 `permission.asked` 事件。
- 当前流程等待 `Deferred.await`，不会继续执行。

3. reply 决定放行范围
- `once`：只放当前请求。
- `always`：把模式写入 approved，并尝试放行同会话中可自动通过的待审请求。
- `reject`：拒绝当前请求，并级联拒绝同会话待审项。

4. disabled 机制做工具级裁剪
- `Permission.disabled(...)` 可把规则投影成“当前 agent 不可用工具集合”。

## implication 是什么 (Harness Implication)
- 安全边界应落在 permission 层，而不是提示词约定。
- `always` 机制能降低重复审批摩擦，但需要配合可审计规则来源。
- 高风险场景可在 ask 前后叠加业务策略（审计、告警、分级批准）。
