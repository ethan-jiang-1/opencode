# 3.8 FileTime：Read-Then-Write 的会话级并发与陈旧写保护

## 源码是什么 (Source)
- `packages/opencode/src/file/time.ts`
- 协同调用：
  - `packages/opencode/src/tool/read.ts` (`FileTime.read`)
  - `packages/opencode/src/tool/write.ts` (`FileTime.assert/read`)
  - `packages/opencode/src/tool/edit.ts` (`FileTime.withLock/assert/read`)
- 关键符号：
  - `Stamp { read, mtime, size }`
  - `assert(sessionID, filepath)`
  - `withLock(filepath, fn)`

## 解读是什么 (Interpretation)
FileTime 是“会话内乐观并发控制 (OCC)”。

1. 每个会话保存自己的读快照
- `reads: Map<SessionID, Map<filepath, Stamp>>`
- `read()` 时记录读取时刻、mtime、size。

2. 写前必须证明“你看过且没变”
- `assert()` 先检查会话里是否有该文件 read stamp。
- 再比较当前 mtime/size 与历史 stamp；不一致则拒绝写入并提示“请先重新 read”。

3. 同文件写操作可串行化
- `withLock(filepath, fn)` 使用 semaphore 1 permit，防止并发 edit 互相覆盖。

4. 可被全局开关关闭
- `OPENCODE_DISABLE_FILETIME_CHECK` 为 true 时跳过 assert。

## implication 是什么 (Harness Implication)
- 这是防止“模型基于旧上下文覆盖新内容”的关键层，不应只靠 prompt 约束。
- 如果你扩展新写工具，应该复用 `assert + withLock + read` 这一套闭环。
- 会话隔离意味着：A 会话 read 过并不代表 B 会话可直接写。
