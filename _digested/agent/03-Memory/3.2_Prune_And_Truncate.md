# 3.2 Prune 与 Truncate：双层内存防线

## 源码是什么 (Source)
- `packages/opencode/src/session/compaction.ts`
- `packages/opencode/src/tool/truncate.ts`
- 协同源码：
  - `packages/opencode/src/session/prompt.ts`（`resolveTools` 内调用截断）
- 关键符号：
  - `PRUNE_MINIMUM = 20_000`
  - `PRUNE_PROTECT = 40_000`
  - `PRUNE_PROTECTED_TOOLS = ["skill"]`
  - `Truncate.output(...)`

## 解读是什么 (Interpretation)
OpenCode 不是只在 overflow 时压缩；它还有“实时截断 + 事后回收”两级机制。

1. Truncate 是执行时防线
- 工具输出超出 `MAX_LINES/MAX_BYTES` 时，原文落盘到 `TRUNCATION_DIR`。
- 返回预览片段 + 引导提示，并标记 `truncated`/`outputPath`。

2. Prune 是回合后防线
- `prune` 倒序扫描历史 completed tool output，累计到 `PRUNE_PROTECT` 后开始标记待裁剪。
- 仅当累计可回收超过 `PRUNE_MINIMUM` 才真正写回 compacted。

3. 有保留白名单和止损点
- `skill` 工具输出默认保护，不参与常规回收。
- 命中已 compacted 时间戳后会停止继续向旧历史扩散。

4. 两层机制互补
- Truncate 防单次爆量。
- Prune 防长会话沉积。

## implication 是什么 (Harness Implication)
- 自定义高噪声工具必须接 `Truncate.output`，否则很容易把上下文打爆。
- `PRUNE_PROTECTED_TOOLS` 决定长期记忆保留策略，是可调的业务治理点。
- 稳定长跑能力来自这类“粗暴但确定”的剪裁策略，不是模型更聪明。
