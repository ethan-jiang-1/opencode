# 3.3 MessageV2 适配器：从图谱消息到模型消息的降维器

## 源码是什么 (Source)
- `packages/opencode/src/session/message-v2.ts`
- 关键符号：
  - `Part / Info / WithParts` 全量 schema
  - `toModelMessages(input, model, options?)`
  - `filterCompacted(stream)`
  - `fromError(e, ctx)`

## 解读是什么 (Interpretation)
`MessageV2` 真正关键不只是 schema，而是“适配器行为”：

1. User/Assistant 的 Part 并非 1:1 透传
- `compaction` part 会转成文本提示 “What did we do so far?”
- `subtask` part 会转成提示文本，避免模型上下文结构断裂。

2. Tool state 被强制补齐“闭环”
- `pending/running` 工具会被映射成 `output-error`（interrupted 占位）。
- 这是为避免 Anthropic 一类接口出现 dangling tool_use。

3. Tool output 的 media 处理是 provider-sensitive
- 先判断 provider 是否支持 tool result media。
- 不支持时，把图片/PDF 从工具结果抽出，额外注入一个 user message 作为 file part。

4. Compacted 工具输出会退化为占位文本
- `part.state.time.compacted` 时输出 `[Old tool result content cleared]`。

5. providerMetadata 只在“同模型回放”时保留
- 如果历史消息来自不同 provider/model，会剥离 metadata，减少跨模型污染。

6. 错误归一层覆盖网络、解压、API、provider 自定义错误
- `fromError` 会映射到 `AuthError/APIError/ContextOverflowError/...`。
- 对 Bun fetch 解压失败（`ZlibError`）有单独重试语义。

## implication 是什么 (Harness Implication)
- “多 provider 兼容”不是靠 prompt 兜底，而是靠消息适配器把上下游协议差异吸收掉。
- 你如果要引入新内容类型（比如 CAD、音频），最安全入口是先扩 Part schema + `toModelMessages` 适配。
- 任何工具系统若不保证 tool-use/tool-result 闭环，在 Anthropic 生态会频繁炸协议。
