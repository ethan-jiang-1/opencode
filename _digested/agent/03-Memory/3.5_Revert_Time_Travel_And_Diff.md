# 3.5 会话时光倒流：Revert 的快照回退与差异复算

## 源码是什么 (Source)
- `packages/opencode/src/session/revert.ts`
- `packages/opencode/src/session/summary.ts`
- 关键符号：
  - `SessionRevert.revert(...) / unrevert(...) / cleanup(...)`
  - `Snapshot.track/revert/restore/diff`
  - `SessionSummary.computeDiff(...)`

## 解读是什么 (Interpretation)
Revert 在 OpenCode 里不是“删聊天记录”，而是“状态回滚协议”：

1. 先断言运行态
- `SessionPrompt.assertNotBusy` 确保回退时没有并发运行中的 loop。

2. 确定回退锚点
- 支持回退到 `messageID` 或 `partID`。
- 若是 part 级回退，会根据“是否还剩有效 text/tool part”决定是否提升到 message 级回退。

3. 快照与 patch 反演
- 扫描回退点之后的 `patch` part，喂给 `Snapshot.revert(...)`。
- 同时维护 `revert.snapshot` 与 `revert.diff`。

4. 差异重算并发布
- 调 `SessionSummary.computeDiff(...)` 计算区间文件变化。
- 写入 `Storage["session_diff"]`，并 `Bus.publish(Session.Event.Diff)`。

5. cleanup 才执行“物理裁剪”
- 用 `SyncEvent` 删除 message/part 投影记录。
- 最后 `Session.clearRevert` 收口。

## implication 是什么 (Harness Implication)
- 可逆编辑必须建立在“文件快照 + 消息锚点”双轨机制上，单靠对话历史无法可靠回滚。
- 如果你要做 IDE 里的可视化 time-travel，`session_diff` 是天然数据源。
- part 级回退语义非常适合做“只撤销某次工具调用”，比整轮撤销更细。
