# 3.6 溢出判决公式：预留预算如何触发 Compaction

## 源码是什么 (Source)
- `packages/opencode/src/session/overflow.ts`
- 关键符号：
  - `isOverflow({ cfg, tokens, model })`
  - `COMPACTION_BUFFER = 20_000`

## 解读是什么 (Interpretation)
OpenCode 的溢出判决不是“看到大就压缩”，而是预算模型：

1. 先看开关
- `cfg.compaction.auto === false` 直接禁用自动判溢出。

2. token 计数
- 优先 `tokens.total`。
- 否则用 `input + output + cache.read + cache.write`。

3. 预留区计算
- `reserved = cfg.compaction.reserved ?? min(20k, maxOutputTokens(model))`
- 本质是在输入窗口里预留一块“输出与余量安全带”。

4. 可用上限
- 有 `model.limit.input`：`usable = inputLimit - reserved`
- 否则：`usable = contextLimit - maxOutputTokens(model)`

5. 判定
- `count >= usable` 即 overflow。

## implication 是什么 (Harness Implication)
- 这意味着“触发 compaction 的早晚”是可配置运营策略，不是固定算法。
- 如果模型输出经常很长，应该提高 `reserved`，否则会出现“刚好没溢出但下步必炸”的抖动。
- 这个预算模型天然适合做不同 agent 的差异化策略（plan 更保守、build 更激进）。
