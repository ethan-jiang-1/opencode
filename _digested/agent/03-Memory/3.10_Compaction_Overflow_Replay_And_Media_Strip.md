# 3.10 Compaction Overflow 模式：回放切点与媒体剥离

## 源码是什么 (Source)
- `packages/opencode/src/session/compaction.ts`
- 协同源码：
  - `packages/opencode/src/session/message-v2.ts`（`toModelMessages(..., { stripMedia: true })`）
- 关键符号：
  - `processCompaction({ overflow })`
  - `replay` 选择逻辑
  - `MessageV2.toModelMessages(msgs, model, { stripMedia: true })`
  - overflow 下 `continue` 分支的 replay/continue synthetic message

## 解读是什么 (Interpretation)
overflow compaction 不是“普通摘要”，而是带恢复语义的两段式流程。

1. 先找“可回放切点”
- 以当前 parent user 为锚点向前扫描，找到最近一个非 compaction 的 user 消息作为 `replay`。
- `messages` 截断到该切点之前，作为压缩输入。
- 若截断后没有足够用户内容，放弃 replay，回退到全量压缩。

2. 压缩输入会强制剥离媒体
- `toModelMessages(..., { stripMedia: true })` 把图片/PDF 等大媒体转占位文本，降低上下文负载。

3. 压缩成功后的恢复策略分两路
- 有 replay：重建一条新的 user 消息，回放原消息内容；媒体 part 转成文本占位。
- 无 replay：写入一条 synthetic “Continue...” 用户提示（overflow 时额外提示媒体过大被移除）。

4. 若 compaction 自身仍溢出，立即 stop
- `result === "compact"` 时写入 `ContextOverflowError`，终止继续循环。

## implication 是什么 (Harness Implication)
- 这是“失败恢复型记忆压缩”，目标不只是减 token，还要恢复任务可继续性。
- 对大附件场景，`stripMedia + replay` 能把会话从硬失败拉回可执行状态。
- 该模式可推广到 RAG/检索失败恢复：先降载再回放关键用户意图。
