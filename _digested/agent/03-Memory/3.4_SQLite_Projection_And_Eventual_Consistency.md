# 3.4 事件投影层：SQLite 持久化与晚到事件容错

## 源码是什么 (Source)
- `packages/opencode/src/session/session.sql.ts`
- `packages/opencode/src/session/projectors.ts`
- 关键符号：
  - `SessionTable / MessageTable / PartTable`
  - `SyncEvent.project(...)`
  - `toPartialRow(...)`
  - `foreign(err)`

## 解读是什么 (Interpretation)
这是一个“事件写模型 -> SQLite 投影”的体系，不是直接 ORM CRUD：

1. 表模型
- `session`：会话元数据、summary、revert、permission。
- `message`：消息 info（JSON）。
- `part`：消息分片 data（JSON）。

2. 写入模式
- `message.updated` / `message.part.updated` 采用 `onConflictDoUpdate`。
- 对同 ID 的重复事件是幂等更新，不会膨胀。

3. 晚到事件容错
- 如果触发了 FK 约束（例如 message 已删但 part 晚到），`foreign(err)` 会识别并忽略，系统只告警不崩。

4. 局部更新有硬约束
- `toPartialRow` 不接受 `undefined` 清空字段，必须显式传 `null`。
- 这是为避免“无意漏字段”导致脏覆盖。

## implication 是什么 (Harness Implication)
- 这层体现了“最终一致性优先于瞬时强一致”：晚到事件可丢，但主流程不应被拖死。
- 如果你要加新的会话级状态字段，首要是补 `session.sql.ts + toPartialRow + projector` 三件套。
- 做外部审计或回放时，应把 `message/part` 当事件流视图，不要把它误当业务最终态。
