# 2.6 Status 通道：会话忙闲与重试状态的外显面

## 源码是什么 (Source)
- `packages/opencode/src/session/status.ts`
- `packages/opencode/src/session/retry.ts`（协同）
- 关键符号：
  - `SessionStatus.Info = idle | busy | retry`
  - `SessionStatus.Event.Status/Idle`
  - `SessionStatus.set/get/list`

## 解读是什么 (Interpretation)
`status.ts` 是一个轻量状态总线，不写库，只维护运行时 map 并发事件：

1. 状态机非常小，但语义强
- `idle`: 空闲
- `busy`: 执行中
- `retry`: 第 N 次重试、错误消息、下次时间戳

2. set 会触发总线广播
- 每次 `set` 发布 `session.status`。
- 设为 `idle` 时会额外发布 `session.idle`（兼容旧事件）。

3. idle 时自动清理 map
- 内存 map 不长期保存 idle 状态，避免无意义常驻条目。

4. retry 面与 `SessionRetry.policy` 对接
- retry policy 里可调用 `opts.set(...)` 回填 attempt/message/next。
- UI 能据此展示“正在重试，预计何时再次尝试”。

## implication 是什么 (Harness Implication)
- 如果要做跨端观测（CLI/TUI/IDE/Web），优先消费 status bus，不要靠日志猜流程。
- retry 不是后台黑箱；应对用户可见，否则会被误判为“卡死”。
- 这个通道很适合接 watchdog 或 SLA 监控（例如 busy 超时报警）。
