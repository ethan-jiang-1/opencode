# 2.5 Session 服务层：事件驱动写模型与运行时桥接

## 源码是什么 (Source)
- `packages/opencode/src/session/index.ts`
- 关键符号：
  - `Session.Service` 接口与 `layer`
  - `SyncEvent.run(Event.Created/Updated/Deleted)`
  - `updateMessage/updatePart/removeMessage/removePart`
  - `fork(...)`, `initialize(...)`, `getUsage(...)`

## 解读是什么 (Interpretation)
`session/index.ts` 是会话域的“服务外壳”，它把数据库、事件、运行时动作统一在一个 Effect Service 里：

1. 持久化写入不是直写 DB，而是事件优先
- `create/patch/remove` 等操作都通过 `SyncEvent.run(...)` 发事件。
- 真正的表更新由 projector 消费事件完成。

2. Message/Part 更新同样事件化
- `updateMessage` -> `message.updated`
- `updatePart` -> `message.part.updated`
- remove 也对应 removed 事件。

3. fork 是“消息树克隆”而非简单复制
- 复制消息时重映射 message id。
- assistant 的 `parentID` 会按新 id map 重连，保住拓扑关系。
- part 逐条重写 id/sessionID/messageID。

4. initialize 是命令桥接
- `initialize(...)` 最终走 `SessionPrompt.command(..., Command.Default.INIT)`。
- 会话服务层可触发 prompt 层流程。

5. usage 计费在会话域里统一折算
- `getUsage` 对 cache read/write、reasoning token、provider metadata 做统一成本计算。
- 并处理 AI SDK v6 下 input token 含缓存的差异（做 adjusted input）。

## implication 是什么 (Harness Implication)
- 这是典型 CQRS/Event-Sourcing 轮廓：写路径应走事件，读路径读投影。
- 要扩展会话语义（新字段、新副作用），优先加 event+projector，不要偷偷直接改表。
- fork 的“拓扑重连”是关键：多分支会话能力建立在 parentID map 正确性之上。
