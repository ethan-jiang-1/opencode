# 2.7 Todo 侧通道：计划状态的独立持久化与广播

## 源码是什么 (Source)
- `packages/opencode/src/session/todo.ts`
- `packages/opencode/src/session/session.sql.ts` (`TodoTable`)
- 关键符号：
  - `Todo.update({ sessionID, todos })`
  - `Todo.get(sessionID)`
  - `todo.updated` bus event

## 解读是什么 (Interpretation)
Todo 并不混在 message parts，而是单独 sidecar 表：

1. 更新策略是“整表替换”
- `update` 事务里先删该 session 所有 todo，再按 position 重插。
- 模型输出计划可直接覆盖，不走逐项 diff。

2. 读取有稳定顺序
- 按 `position asc` 读回，UI 展示顺序可预测。

3. 有独立事件通道
- `Todo.update` 后发布 `todo.updated`。
- 上层可以单独订阅计划变化，不必扫描消息流。

## implication 是什么 (Harness Implication)
- 计划面板最好依赖 todo sidecar，而不是从文本消息反解析。
- “整表替换”牺牲了增量效率，换来协议简单和一致性，适合 Agent 反复重排计划的场景。
- 若后续要加计划审计历史，可在 sidecar 层单独扩展，不污染主消息图。
