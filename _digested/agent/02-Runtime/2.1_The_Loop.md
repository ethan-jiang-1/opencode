# 2.1 The Loop：会话执行的主状态机

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- 协同源码：
  - `packages/opencode/src/session/processor.ts`
  - `packages/opencode/src/session/compaction.ts`
  - `packages/opencode/src/session/system.ts`
- 关键符号：
  - `runLoop(...)`
  - `handleSubtask(...)`
  - `resolveTools(...)`
  - `insertReminders(...)`
  - `compaction.create/process`

## 解读是什么 (Interpretation)
`runLoop` 不是“问一次模型”流程，而是一个会话级状态机。

1. 每轮都重建上下文与执行面
- 从 `MessageV2.filterCompacted(...)` 拿当前有效历史。
- 重新解析 agent/model/tools/system，再进入本轮推理。

2. 特殊任务优先于常规推理
- 如果历史里有未处理 `subtask/compaction` part，会先走 `handleSubtask` 或 `compaction.process`。
- 这让“后台任务”成为一等执行路径，而不是 prompt 技巧。

3. 模型调用前有多层注入点
- `insertReminders` 会插入合成提醒（plan/build 切换等）。
- `plugin.trigger("experimental.chat.messages.transform")` 在发模型前可改写消息。
- 系统提示由 `environment + skills + instructions` 组装。

4. 循环通过显式 gate 控制 `break/continue`
- `processor.process(...)` 返回 `continue/stop/compact`。
- `compact` 会创建 compaction user part，下一轮先压缩再继续。
- tool-calls、overflow、finish 条件共同决定是否退出。

## implication 是什么 (Harness Implication)
- 主循环是“调度器”，不是“单次 LLM 请求包装器”。
- 想扩展行为，优先增加结构化 part/hook，而不是堆系统提示词。
- 大任务稳定性来自循环 gate（subtask、compaction、stop），不是模型自觉。
