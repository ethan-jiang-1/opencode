# 2.1 心跳引擎与主循环 (The Loop)

在所有的 AI Coding Assistant 中，决定其“自治度 (Autonomy)”与“稳定性 (Stability)”的核心，就是它的主循环设计。
本系列之前的章节解读了离散的 Agent、Permissions 和 Tools，而 `prompt.ts` 下的 `runLoop` 就是把这些元素串起来的这根“引线”。

## ⏳ runLoop 时序全貌图 (Sequence Diagram)

每一次用户按下回车键（或是 Agent 上一步调用了某个 Tool 返回），都会触发一次 Loop 轮回。
让我们直击源码深处，这幅图精准还原了 `while(true)` 的单次生命周期：

```mermaid
sequenceDiagram
    participant User/System as 历史记录 (msgs)
    participant Loop as 核心控制器 (runLoop)
    participant Effect as 环境与插件层
    participant Processor as 大模型对接引擎
    participant Tool as 沙盒工具层

    rect rgb(30, 30, 40)
        Note over User/System, Tool: --- 开始一轮死循环 while(true) ---
    end
    
    User/System->>Loop: 提取未压缩的最新对话流
    
    %% Step 1: Compaction 检测
    Loop->>Loop: 检测最新是否是 compation 标记
    alt 需要压缩
        Loop->>Effect: 召唤幽灵 Agent 提炼历史
        Effect-->>User/System: 插入带 summary 标志的快照
        Loop->>Loop: break 跳转，下一轮重置
    end
    
    %% Step 2: 组装期
    Loop->>Effect: 触发 `Plugin.trigger(transform)` <br/> (这是外挂 RAG 最好的切点)
    Loop->>Effect: 收集环境特征 (OS, 工作区, LSP)
    Loop->>Effect: 收集 Agent Skills (自定义规范)
    Effect-->>Loop: 强力组合而成的 System Prompt Array
    
    %% Step 3: LLM 调度
    Loop->>Processor: 下发 messages 和 permitted tools
    Processor->>Processor: 调用 streamText (AI 回传流)
    
    alt 收到普通文本回复
        Processor-->>Loop: 返回 finish: "stop"
        Loop->>Loop: break 结束本次主循环
    else 收到 Tool-Calls
        Processor->>Tool: 执行如 read_file / bash
        Tool-->>Processor: 如果崩了？抛弃异常，捕获堆栈要求 LLM 重试
        Processor-->>Loop: 返回带有执行状态的 message
        Loop->>Loop: continue 继续下一次搏动
    end
```

## 🧠 极客向解读：为什么这个循环如此高级？

如果你随手写过一个基于 OpenAI `chat.completions.create` 的 while 循环，你很快就会感觉到 OpenCode `runLoop` 的三层降维打击：

1. **绝对拦截权在框架，不在 LLM。**
   你看最下方的判断，普通的框架是把大模型的“胡说八道”直接喂回给用户。但在 OpenCode 中，Tool 执行前必须要过严格的 `Permission` 网（如上一节所说）。如果在循环中发生了危险请求，`runLoop` 会触发 `bus.publish`，将执行流挂起（Suspend），直到在另一个 Terminal 会话里用户通过了审批，循环才会继续。
2. **“失常”恢复机制（Self-Correction）**。
   大模型经常因为缩进错误导致文件替换失败。在普通的循环里，它会放弃。但是 `Processor` 工具层拦截了全部未捕获的 Error。这些 Error 会作为 `ToolResultPart` 原路塞入下一轮循环。LLM 看到满屏报错红字后，会在下一次搏动中尝试自我纠正。
3. **副作用隔离**。
   所有的调度不是 `async/await` 那么简单，而是 `yield* Effect...`。当用户在控制台中按下 `Ctrl+C` 试图中断正在发疯的代码修改时，Effect 的中断树 (Interruption Context) 会立刻自顶向下层层劈断这颗流转树，连正在进行的底层 socket 连接都能瞬间安全掐断。

## 💡 Harness 启示

不要试图在这个死循环的“中间”和它对话。
Harness 的王道，是在 `while(true)` 开始**之前**（甚至更早的 Session Init 阶段）设置好结界（Permissions），或者在它每次准备向大模型发请求前的那一瞬（`System Assembly` 阶段），偷偷在这个循环里加上一段你想要扭转它认知的提示（见后续的 Hooks 和 Subtasks 章节）。
