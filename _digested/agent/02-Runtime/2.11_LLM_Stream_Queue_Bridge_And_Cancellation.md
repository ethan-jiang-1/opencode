# 2.11 LLM 服务层：AsyncIterable 到 Effect Stream 的桥接器

## 源码是什么 (Source)
- `packages/opencode/src/session/llm.ts`
- 关键符号：
  - `LLM.Service.stream(input)`
  - `Effect.acquireRelease(new AbortController, ctrl.abort)`
  - `Queue.unbounded<Event, unknown | Cause.Done>()`
  - `for await (const event of result.fullStream) Queue.offerUnsafe(...)`
  - `Effect.onInterrupt(() => ctrl.abort())`

## 解读是什么 (Interpretation)
`LLM.Service.stream` 把 SDK 的异步迭代流包装成可管理的 Effect Stream。

1. 每次请求有独立 AbortController 生命周期
- 创建时注册 release finalizer，scope 结束自动 abort。

2. 原始模型流先落到 queue，再转成 Stream
- 后台 fiber 持续把 `fullStream` 事件写入 queue。
- 写完后 `Queue.endUnsafe(queue)`，通知上游消费结束。

3. 错误与中断都能向上传播
- 后台拉流异常会 `Queue.failCauseUnsafe(...)`。
- 外部中断会触发 `ctrl.abort()`，下游可感知取消。

4. 这层与 provider 细节解耦
- 上游 `SessionProcessor` 只关心统一 `LLM.Event` 序列，不关心 SDK 实现差异。

## implication 是什么 (Harness Implication)
- 如果你替换底层 SDK，保留这层 queue 桥接就能最小化上层改动。
- 取消语义必须贯穿到 provider 请求，不能只停本地事件消费。
- 统一事件流接口是后续重试、状态面板和审计的前提。
