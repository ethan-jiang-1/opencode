# 4.28 `command` 通道：模板编译器与 Subtask 降级器

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- 协同源码：
  - `packages/opencode/src/config/markdown.ts`
- 关键符号：
  - `SessionPrompt.command(input)`
  - `argsRegex / placeholderRegex / quoteTrimRegex`
  - `$1...$n` 与 `$ARGUMENTS` 替换
  - `ConfigMarkdown.shell(...)`（`!` 反引号命令执行）
  - `isSubtask` 判定与 `SubtaskPart` 构造

## 解读是什么 (Interpretation)
`command` 不是字符串拼接，而是小型 DSL 编译流程。

1. 参数解析有专门词法规则
- 保留 `[Image N]`、引号字符串和普通 token。
- 去掉参数外层引号后再进入模板替换。

2. 模板支持位置参数与全量参数
- `$1...$n` 按位置替换。
- 最后一个占位符可吞并剩余参数。
- `$ARGUMENTS` 直接替换完整原始参数串。

3. 模板支持内嵌 shell 求值
- 匹配 `!` 反引号片段，按 `Shell.preferred()` 执行并回填结果。

4. 命令可降级为 subtask 而非直接主线程执行
- agent 为 subagent 且允许 subtask 时，会创建 `SubtaskPart`。
- 主会话后续由 `runLoop` 识别该 part，再走 `task` 工具处理。

5. 最终仍走统一 `prompt(...)` 写入会话
- command 产出的 parts 通过 `prompt` 入库，随后走标准 runLoop 生命周期。

## implication 是什么 (Harness Implication)
- 这层让“命令系统”具备可组合模板能力，而不是硬编码脚本。
- subtask lowering 让命令天然支持并行或隔离执行，不污染主代理上下文。
- 若扩展命令语法，优先加在编译阶段（解析/替换），保持后续执行通道稳定。
