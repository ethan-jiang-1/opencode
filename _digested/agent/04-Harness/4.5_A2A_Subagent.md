# 4.5 A2A Subagent：子任务并行与上下文隔离

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- 协同源码：
  - `packages/opencode/src/tool/task.ts`
  - `packages/opencode/src/agent/agent.ts`
- 关键符号：
  - `runLoop(...)` 中 `task?.type === "subtask"`
  - `handleSubtask(...)`
  - `TaskTool.execute(...)`
  - `Session.create({ parentID: ... })`
  - synthetic 汇总消息：`Summarize the task tool output above...`

## 解读是什么 (Interpretation)
Subagent 不是“让主模型自己多想几步”，而是启动独立子会话执行。

1. 触发路径是结构化 part
- 主循环检测到 `subtask` part 后进入 `handleSubtask`，优先于常规模型推理。
- 子任务在主会话中以 `tool` part 状态机可追踪。

2. 真实执行由 `task` 工具完成
- `TaskTool` 会创建或复用子 session（支持 `task_id` 续跑）。
- 子 session 带独立权限收敛（可禁 `task/todowrite` 等），并调用 `SessionPrompt.prompt`。

3. 主干只回收提纯结果
- 主会话记录的是 `task` 工具输出摘要，不直接并入子会话全量历史。
- 可选插入 synthetic user part，强制主模型先总结子任务结果再继续。

4. 取消与失败都有显式收口
- 中断会把 tool part 标记为 error/cancelled。
- 正常完成则写入 `status: completed` 与 metadata（sessionId/model）。

## implication 是什么 (Harness Implication)
- 大任务应优先“拆子任务再汇总”，而不是在单会话里硬撑上下文。
- 子会话隔离让并行探索更安全，避免主上下文被噪声日志污染。
- 设计 subtask prompt 时要短而明确，否则并行会放大不确定性。
