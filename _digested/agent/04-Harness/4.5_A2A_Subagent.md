# 4.5 Agent-to-Agent (A2A) 编排与 Subtask 注入

A2A，即 Agent to Agent 的通讯协作，是构建高维 Harness 时不可逾越的设计高地。单脑大模型终究会受制于上下文迷失 (Context Window Overflow) 与逻辑碎片化（Logic Fragmentation）。
我们在上一节看完了静态规则（Skill）、拉取知识资源（MCP）和充当无头服务（ACP）的外部扩展。
这一节，我们将探讨：**Agent 如何孵化 (Spawn) 并指挥其他 Agent 完成大型需求**。

## 🔬 OpenCode 是怎么做的？

在 `prompt.ts` 中，`runLoop` 包含这几行重磅级的代码：

```typescript
// Subtask 拦截机制
const task = msg.parts.find(p => p.type === "subtask");

if (task?.type === "subtask") {
    // 发生了维度折叠！
    yield* handleSubtask({ task, model, lastUser, sessionID, session, msgs })
    continue
}
```

**Subtask 模型：**
对于 OpenCode 来说，A2A 并不神秘。当一个高智的主理人（Orchestrator, 例如 `plan` Agent）认为前方有几个不需要上下文但很具体的微小工序时。它不会自己去修改文件。
它生成了一个包含 `type: "subtask"`, `agent: "explore"` (或特定的名称)，`prompt: "去搜索 redis 相关的配置"` 的 JSON 对象。

`handleSubtask` 的底层魔力在于：它新开了一个**物理隔离的新版 `msgs` 流 (环境)**。
新的小 Agent 完全看不到大 Agent 那啰嗦的上级需求，它只被告知最底层的目标。
它的产出随后会被精炼，作为一段普通对话流塞回大 Agent 的记忆中。大 Agent 醒来：“原来小伙计们搞定了。”

## 💡 实战案例：如何利用 A2A 让代码审查 (Review) 自我纠正？

如果你在企业里部署 OpenCode，你需要建立一套**自动化的重构+安全检查流水线 Harness。**

**我们设计两个角色 (Agent.Info) :**
- `coder_agent`：权限全开，能写代码。
- `auditor_agent`：极小参数模型/快速执行，只能读取，但配好了包含《OWASP 安全代码准则》的系统 Prompt。

**Harness 运行流转 :**
1. 用户下发命令至 `coder_agent`：要求替换某个老旧的表单接口。
2. `coder_agent` 使用它的工具。
3. 如果你想让其拥有“审查能力”，你就在 `Skill` 或 `Prompt` 里硬性教它："每当你完成一整个文件的重构，生成一个 `subtask` 块丢给 `auditor_agent` 做复查"。
4. 于是 `coder_agent` 输出了 `subtask` 返回，`runLoop` 捕获它，并在新隔离的环境内拉起并喂给了 `auditor_agent` 当前变动的文件与旧文件。（你甚至不需要亲自实现这个调度框架，底层的 `handleSubtask` 处理了一切）
5. `auditor_agent` 看完，冷冷抛出一句："第 45 行参数没有做 SQL 注入过滤拦截"。这段话带着强烈的审查语气被包回主节点的 `msgs` 中。
6. `coder_agent` 继续主循环（它的上一段记忆是被强加的 Review 回复），它立刻意识到缺陷并调取编辑器 Tool 将其修正。

在这一切结束后，真正的用户仅仅是喝了口水。

这就是依靠 `subtask` 数据结构和底层隔离循环缔造出的**原生 A2A（多智能体编排）机制**。它的效率极其高，最关键的是：避免了记忆混淆。
