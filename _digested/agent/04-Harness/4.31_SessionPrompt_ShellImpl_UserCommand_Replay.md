# 4.31 `shellImpl`：用户手动命令的会话回放通道

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- 关键符号：
  - `SessionPrompt.shell(...)` -> `runner.startShell(...)`
  - `shellImpl(input, signal)`
  - shell invocation map (`zsh/bash/pwsh/cmd/...`)
  - `plugin.trigger("shell.env", ...)`
  - tool part 实时 metadata 更新与 abort 收尾

## 解读是什么 (Interpretation)
`shellImpl` 把“用户直接执行命令”也纳入统一会话语义。

1. 会话里会显式写入一组消息
- 先写一条 user synthetic 文本（说明用户执行了工具）。
- 再写 assistant message + `tool=bash` running part，形成完整审计轨迹。

2. 不同 shell 有不同启动脚本
- `zsh/bash` 会 source 常见 rc 文件后执行命令。
- `pwsh/cmd/fish/nu` 走各自参数模板。

3. 输出是流式写回 tool metadata
- stdout/stderr 持续累积 `output`，并不断更新 running part 元数据。

4. 取消与结束都走统一收尾
- abort 会 kill process tree，并在输出追加“User aborted”标记。
- 结束时写 completed 状态与完整 output，assistant message 标记 completed time。

## implication 是什么 (Harness Implication)
- 用户手动动作被并入同一消息图后，后续模型能基于真实执行结果继续推理。
- 这条通道避免“终端里发生了事但会话不知道”的上下文断层。
- 若要接入 IDE 内置终端，应优先复用该回放语义而不是旁路写日志。
