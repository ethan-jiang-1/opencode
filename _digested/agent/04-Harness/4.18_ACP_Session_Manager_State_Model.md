# 4.18 ACP Session Manager：跨协议会话状态缓存模型

## 源码是什么 (Source)
- `packages/opencode/src/acp/session.ts`
- `packages/opencode/src/acp/types.ts`
- 关键符号：
  - `ACPSessionManager`
  - `ACPSessionState { id,cwd,mcpServers,createdAt,model,variant,modeId }`
  - `create/load/get/setModel/setVariant/setMode`

## 解读是什么 (Interpretation)
ACP 层维护了一份本地 session state cache，专门服务协议转换：

1. create/load 都会回填缓存
- `create` 调 opencode `session.create` 后写 cache。
- `load` 先向后端校验 session 存在，再写 cache。

2. get 是强约束访问点
- session 不存在时抛 ACP `invalidParams`，不是返回空值。

3. model/variant/mode 是可独立更新字段
- UI 的 model/mode 切换不会重建会话，只更新 cache 字段。

4. tryGet 用于事件处理路径
- event 流到来时若 session 不在 cache，直接忽略，避免跨会话噪音。

## implication 是什么 (Harness Implication)
- 这是 ACP translator 的“内存控制面”，不能省；否则协议请求将无法无状态处理。
- 把 model/variant/mode 与后端解耦缓存，可减少 RPC 读放大。
- 若要做多客户端协同，需考虑这份本地 cache 的失效策略与重同步机制。
