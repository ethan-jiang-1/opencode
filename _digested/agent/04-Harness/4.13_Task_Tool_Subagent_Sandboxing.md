# 4.13 `task` 工具：子 Agent 会话编排与权限继承防泄漏

## 源码是什么 (Source)
- `packages/opencode/src/tool/task.ts`
- 关键符号：
  - `TaskTool.execute(...)`
  - `Permission.evaluate("task", ...)`
  - `Session.create({ parentID, permission })`
  - `SessionPrompt.prompt(...)`

## 解读是什么 (Interpretation)
`task` 的本质是“把 subagent 调度显式化”：

1. 可见 agent 列表会先做权限过滤
- 调用者若无某子 agent 的 `task` 权限，该 agent 不会出现在可选列表。

2. 默认会 ask `task` 权限
- 除非显式 `bypassAgentCheck`（如用户显式 @ 调用或命令触发）。

3. 子会话不是裸继承
- 新建子 session 时，会根据子 agent 权限补 deny 规则：
  - 没 `todowrite` 就 deny `todowrite`
  - 没 `task` 就 deny `task`
- 还会把 `experimental.primary_tools` 在子任务中禁掉，防止能力外溢。

4. 可恢复任务
- 传 `task_id` 时尝试复用历史子 session。
- 输出显式返回 `task_id`，便于后续续跑。

5. 取消联动
- 父上下文 abort 时，触发 `SessionPrompt.cancel(childSession)`。

## implication 是什么 (Harness Implication)
- 这是一套“可控并发”机制：既能并发调度，又不让子 agent 权限无限膨胀。
- 做复杂流水线时，应优先通过 `task_id` 续跑而不是重建，以保留子树上下文。
- 如果你要引入自定义 subagent，先想清楚它是否应该拥有 `task/todowrite`，否则会形成递归放大器。
