# 4.24 `bash` 工具：AST 路径解析与权限合成器

> 收敛说明：本篇偏源码机制。端到端执行叙事请看 [4.6_The_Bash_Tool.md](./4.6_The_Bash_Tool.md)。

## 源码是什么 (Source)
- `packages/opencode/src/tool/bash.ts`
- 协同源码：
  - `packages/opencode/src/permission/arity.ts`
- 关键符号：
  - `parse(...)`（tree-sitter bash/powershell）
  - `collect(root, cwd, ps, shell)`
  - `argPath/resolvePath/cygpath`
  - `ask(ctx, scan)`（`external_directory` + `bash`）
  - `run(...)`（`Shell.killTree`, timeout, metadata preview）

## 解读是什么 (Interpretation)
`bash` 在执行前，会先把命令变成可判定的权限请求集合。

1. 语法树解析优先于执行
- 用 tree-sitter 分别解析 bash 与 powershell。
- 从 AST 提取 command tokens，而不是做脆弱字符串 split。

2. 参数路径解析兼容多壳语法
- 处理 `~`、`$env:VAR`、`${env:VAR}`、`filesystem::` provider 前缀。
- Windows 下可通过 `cygpath` 把 posix 路径还原成 windows 路径。

3. 扫描结果被分成三类
- `dirs`: 潜在外部目录触达（用于 `external_directory` 权限）。
- `patterns`: 具体命令文本（用于 `bash` ask）。
- `always`: 基于 `BashArity.prefix(tokens)` 生成稳定允许前缀。

4. ask 是两阶段
- 先 external_directory，再 bash。
- 若 `workdir` 已在仓库外，也会被加入 `dirs` 强制审批。

5. 运行期保持可观测并可终止
- stdout/stderr 持续推送到 `ctx.metadata.output`（有 preview 截断）。
- timeout 或用户 abort 都会 `killTree` 并在输出尾部写 `<bash_metadata>`。

## implication 是什么 (Harness Implication)
- 通过 AST 扫描把“命令执行权限”前移到执行前，是 Bash 可控化的关键。
- `BashArity` 让长期授权可以对齐“命令意图前缀”，避免过细或过宽授权。
- 任何替代 bash 实现若省略 `collect+ask`，都会回退成高风险黑箱执行。
