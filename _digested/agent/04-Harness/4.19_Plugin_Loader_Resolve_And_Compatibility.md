# 4.19 Plugin Loader：解析阶段、入口阶段、兼容阶段三段闸门

## 源码是什么 (Source)
- `packages/opencode/src/plugin/loader.ts`
- `packages/opencode/src/plugin/shared.ts`
- 关键符号：
  - `PluginLoader.plan/resolve/load`
  - `resolvePluginTarget(...)`
  - `createPluginEntry(...)`
  - `checkPluginCompatibility(...)`

## 解读是什么 (Interpretation)
插件加载被拆成可观测阶段，不是一个黑盒 `import()`：

1. plan 阶段
- 规范化 spec/options，并标记是否命中过时插件包。

2. resolve 阶段（带错误 stage）
- `install`：无法解析或安装 target
- `entry`：找不到合法入口
- `compatibility`：engines.opencode 不兼容

3. load 阶段
- 对 entry 做动态导入，失败单独报错。

4. shared 提供强约束入口解析
- 区分 path plugin 与 npm plugin。
- 防目录穿越：package export 解析结果必须在插件目录内。
- 支持 `exports["./server"|"./tui"]`、`main`、目录 index 兜底。

## implication 是什么 (Harness Implication)
- 分阶段错误对可运营性极关键：用户能知道到底是安装失败还是版本不兼容。
- 入口路径 containment 检查是供应链安全必需，不可弱化。
- 要支持更多插件形态时，应先扩 `shared.ts` 的解析策略，而不是改业务层。
