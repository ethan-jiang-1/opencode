# 4.9 MCP 深水区：多传输降级、缓存索引与 OAuth 闭环

## 源码是什么 (Source)
- `packages/opencode/src/mcp/index.ts`
- 关键符号：
  - `connectRemote/connectLocal/create`
  - `tools/prompts/resources`
  - `startAuth/authenticate/finishAuth/removeAuth`
  - `pendingOAuthTransports`

## 解读是什么 (Interpretation)
MCP 层不是简单 client wrapper，而是“连接管理器 + 协议桥”：

1. Remote 连接是双传输回退
- 先尝试 `StreamableHTTP`，失败再尝试 `SSE`。
- 本质是运行时容灾，不把 transport 选择交给用户手配。

2. Local 连接走 stdio，并注入工作目录/环境
- `StdioClientTransport` + `command args cwd env`。

3. 状态缓存三元组
- `status`：连接状态。
- `clients`：活连接对象。
- `defs`：缓存工具定义（tool list）。

4. 动态工具面
- MCP 工具被转换成 AI SDK `dynamicTool`。
- 工具 id 统一做 `sanitize(client) + sanitize(tool)` 命名空间化。

5. Tool list 热更新
- 监听 `ToolListChangedNotification`，收到后刷新 defs 并发布 `mcp.tools.changed`。

6. OAuth 流程闭环
- `startAuth` 生成 `oauthState` 并保存。
- `authenticate` 负责拉起浏览器 + 等待 callback。
- `finishAuth` 用 `pendingOAuthTransports` 完成 token 交换。
- 校验 state 防 CSRF，成功后重连并更新状态。

7. 资源安全收口
- service finalizer 会关闭 client，并尝试清理子进程。

## implication 是什么 (Harness Implication)
- 如果你要把私有数据源长期挂给 Agent，MCP 是“托管连接层”，不是“单次请求层”。
- 企业内网经常协议不稳，双 transport 回退是必须品，不是优化项。
- OAuth 流必须保存并校验 state；少这一步就不是工程系统，是 demo。
