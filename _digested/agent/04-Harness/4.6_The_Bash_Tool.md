# 4.6 Bash Tool 端到端链路：从 ToolCall 到结果回注

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- `packages/opencode/src/session/processor.ts`
- `packages/opencode/src/tool/tool.ts`
- `packages/opencode/src/tool/bash.ts`

> 机制深潜请看 [4.24_BashTool_AST_Path_Resolver_And_Permission_Synthesis.md](./4.24_BashTool_AST_Path_Resolver_And_Permission_Synthesis.md)。

## 解读是什么 (Interpretation)
本篇只看 e2e 主链路。

1. 模型产生 tool-call
- `runLoop` 组织工具与上下文。
- `processor` 捕获 `tool-call` 事件并创建 running tool part。

2. 工具执行前过 schema 与权限
- `tool.ts` 先做参数校验。
- `bash.ts` 再做扫描与 ask，必要时进入人工审批。

3. 执行结果回注消息树
- `bash` 输出经过截断与元数据回写。
- `processor` 接收 `tool-result/tool-error`，落盘 completed/error 状态。

4. 主循环继续或停止
- 工具结果回喂模型进入下一轮。
- 无工具继续、命中 stop 条件或完成回答时退出循环。

## implication 是什么 (Harness Implication)
- 你可以把 bash 看成“可控执行器”而非裸命令调用。
- 想提升稳定性，优先改权限/扫描/截断层，而不是只改 prompt。
- 对外讲架构时，本篇可作为最小可解释路径。
