# 4.22 `read` 工具：路径护栏、分页切片与多模态回传

## 源码是什么 (Source)
- `packages/opencode/src/tool/read.ts`
- 关键符号：
  - `assertExternalDirectory(...)` + `ctx.ask(permission="read")`
  - `DEFAULT_READ_LIMIT / MAX_LINE_LENGTH / MAX_BYTES`
  - `InstructionPrompt.resolve(...)`
  - MIME 分支（text / directory / image / pdf / binary）

## 解读是什么 (Interpretation)
`read` 不是“读文件字符串”，而是一个带安全与预算控制的统一读取入口。

1. 路径先标准化再做越界审计
- 相对路径会解析到 `Instance.directory`。
- Windows 路径会归一化。
- 读前必须经过 external-directory 检查与 read 权限 ask。

2. 目录读取和文件读取共用 offset/limit 协议
- 目录返回 `<entries>` 切片与“继续读取 offset”提示。
- 文件按行读取，输出带行号，支持分段续读。

3. 文本读取有双阈值
- 每行长度上限（超长行截断）。
- 总输出字节上限（默认 50KB），超过即打断并给 `nextOffset`。

4. 非文本按 MIME 分流
- 图片/PDF 返回附件（data URL）+ 简短文本说明。
- 二进制文件（扩展名与采样检测）直接拒绝，避免污染上下文。

5. read 还承担 instruction 注入桥
- `InstructionPrompt.resolve(...)` 会按目标文件邻域加载 AGENTS/CLAUDE 等规则。
- 结果通过 `<system-reminder>` 注入输出，并在 metadata.loaded 记录来源路径。

## implication 是什么 (Harness Implication)
- 统一 offset/limit 协议让 UI 或上层 agent 可稳定实现“渐进阅读”。
- 多模态附件回传可避免把二进制硬转文本造成 token 爆炸。
- 若你做自定义读取工具，建议复刻同样的权限顺序和预算模型。
