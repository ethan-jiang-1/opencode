# 4.2 知识库的供给：静态 Skills 与动态 MCP

Harness 机制要想强，绝不仅靠拦得住报错，还得喂得进高质量上下文。
上一章我们利用 Hook 把知识推入历史栈里是一种暴力而有效的极客打法，而在正常的使用中，OpenCode 还为你的业务扩展提供了一大一小两扇门框：`Skills` 与 `MCP`。它们的结合能应对 90% 以上的企业级私有化研发需求。

## 📚 静态供给站: Skills (企业级词典挂载点)

当你在 `prompt.ts` 继续跟进 `runLoop` 时，第一层知识拼接点就是 `SystemPrompt.skills()`.
在你的本地目录中，通常只要放入特定格式的 Markdown（如 `.opencode/skills/` 里的 `typescript_guideline.md` 等），系统在拼装指令集时，就会将这个 Skill 的内容打入上下文底部。

- 最合适的用途：写死（甚至很少变更）的框架规范和团队打法。例如："在本项目中，禁止写原生的 `fetch` 请求，永远使用 `utils/api.ts` 里提供的拦截器壳子。"
- 工作原理的本质是一套静态路由：你可以把大批量的这类文档配给指定的 Agent 类型。

## 🔌 动态供给站: MCP (Model Context Protocol)

对于很多架构师来说，让 AI 获取项目动态信息，以前最笨的办法就是给大模型写一个 "Tool"，教它使用 `curl`。
但这既低效又容易因为网络超时/验证过期炸毁流程。

**OpenCode 的优雅解法是 MCP 资源化接入。**
源码 `packages/opencode/src/session/prompt.ts` 内置了对 MCP Resource 的全量支持 `mcp.readResource(clientName, uri)`。MCP（模型上下文协议）是由 Anthropic 倡导的一套服务间数据通信标准。

你可以将 MCP 视作一台 **即插即用、带独立权限校验的移动知识拉取端**。

### 实战解析：构建监控运维的 Harness
想象这么一种混合架构情况：当你询问 `build` Agent：“为什么我刚刚跑这个测试的时候挂掉了，请去查看生产服务器今天崩溃的日志。”

1. 如果你只有前端：Agent 只能在 Terminal 里跑 grep，对于不在当前服务器上的日志束手无策。
2. **利用 MCP 构建大框架 (Harness)**: 你只需要在本地注册一个基于 MCP 标准搭建的 `CloudWatch/Datadog Connector Server` 实例。系统底层会将这台服务器暴露出的所有数据集转化为可读的虚拟资源 `URI`。
3. 当 LLM 在循环中，它判断自己急需外部指标时，它不再需要你教它打各种 Bash，它向系统的 `readResource` 请求读取一个特定的监控端点。随后你的本地 MCP Server 会与内网网关通信、拉取日志、去敏，并清洗格式推给 `runLoop` 的下一次循环。

**这完成了对于企业来说最不可多得的知识边界突破**：你的 Agent 原来不仅在这个单薄的 VS Code 或者 Terminal 里工作。在它背后的世界，它可以是安全审批（请求外发）、是海量搜索甚至连接在 Kubernetes 大规模监控集群中。而且这套挂载全部对原始主业务零代码侵入。
