# 4.10 ACP 双向翻译器：事件泵与协议语义映射

## 源码是什么 (Source)
- `packages/opencode/src/acp/agent.ts`
- 关键符号：
  - `runEventSubscription()` / `handleEvent(event)`
  - `processMessage(...)`
  - `prompt(...)`
  - `toToolKind(...)` / `toLocations(...)`

## 解读是什么 (Interpretation)
`acp/agent.ts` 的本质是“协议翻译器”，不是普通 API handler：

1. OpenCode Event -> ACP UI Update
- 订阅全局事件流。
- 把 `message.part.updated/delta` 翻译成 `tool_call_update`、`agent_message_chunk`、`agent_thought_chunk`。

2. Permission Ask 桥接有队列化
- `permission.asked` 按 session 串行处理，避免多个弹窗竞争。
- ACP 选择回写为 `sdk.permission.reply`。

3. Tool 可视化语义映射
- `toToolKind` 把内部工具分类为 ACP 的 `read/edit/search/execute/...`。
- `toLocations` 从工具入参抽取路径，供 IDE 精准标注。

4. 历史回放机制
- `load/fork/resume` 时调用 `processMessage` 重播 tool、text、reasoning、file。
- 这保证 ACP 客户端可恢复完整时序，而不是只拿最终答案。

5. ACP Prompt -> OpenCode Part
- `text` 的 audience 注解被翻译为 `synthetic`（assistant only）或 `ignored`（user only）。
- `resource/resource_link/image` 被降维成 OpenCode `text/file` part。

6. 模型/模式/变体也在协议层做协商
- session manager 维护 model/mode/variant。
- 支持 `available_commands_update`、`setSessionModel`、`setSessionMode`。

## implication 是什么 (Harness Implication)
- 任何要接 OpenCode 的 IDE/网页，不需要触碰 runLoop，本质上实现 ACP translator 即可。
- 如果你的 UI 希望“像本地终端一样细粒度可见”，必须订阅并正确消费 `part.updated/delta` 级事件。
- audience -> synthetic/ignored 的映射非常关键，它决定“只给模型看”与“只给用户看”的边界。
