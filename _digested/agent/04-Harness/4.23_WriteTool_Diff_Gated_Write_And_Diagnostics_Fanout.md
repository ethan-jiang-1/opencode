# 4.23 `write` 工具：Diff 先验审批与 LSP 诊断扇出

## 源码是什么 (Source)
- `packages/opencode/src/tool/write.ts`
- 关键符号：
  - `FileTime.assert/read`
  - `createTwoFilesPatch(...)` + `trimDiff(...)`
  - `ctx.ask(permission="edit", metadata.diff)`
  - `Format.file`, `Bus.publish(File.Event.Edited)`, `FileWatcher.Event.Updated`
  - `LSP.diagnostics()`（当前文件 + 项目其他文件）

## 解读是什么 (Interpretation)
`write` 的主流程是“审前 diff -> 落盘 -> 诊断反馈”。

1. 写前一致性校验
- 若文件已存在，先 `FileTime.assert`，要求先 read 且未被外部改动。

2. 权限审批依赖 diff 而不是裸路径
- 先算旧内容到新内容的 patch，再 `ask(edit)`。
- metadata 带 `filepath + diff`，便于人审或策略引擎判定。

3. 落盘后触发完整生态事件
- `Filesystem.write` -> `Format.file` -> file edited/update 事件。
- `FileTime.read` 立即刷新新 stamp，形成下一轮写入基线。

4. 诊断反馈不仅限目标文件
- 先输出目标文件错误。
- 再附带最多 `MAX_PROJECT_DIAGNOSTICS_FILES` 个项目级错误文件摘要。

## implication 是什么 (Harness Implication)
- 这是“写入工具即诊断回路”，能让模型在同一轮看到语义回归信号。
- `diff` 作为审批元数据很关键，可直接接入企业级策略网关。
- 如果你扩展写工具，不应省略 watcher/LSP 事件，否则会破坏 IDE 同步体验。
