# 4.17 MCP OAuth Callback：本地回调服务与 CSRF 防线

## 源码是什么 (Source)
- `packages/opencode/src/mcp/oauth-provider.ts`
- `packages/opencode/src/mcp/oauth-callback.ts`
- 关键符号：
  - `McpOAuthProvider` (`clientMetadata`, `state`, `saveTokens`, `invalidateCredentials`)
  - `McpOAuthCallback.ensureRunning/waitForCallback/cancelPending`
  - 常量：`OAUTH_CALLBACK_PORT=19876`, `OAUTH_CALLBACK_PATH=/mcp/oauth/callback`

## 解读是什么 (Interpretation)
这套 OAuth 不是“打开浏览器拿 code”这么简单，而是完整闭环：

1. provider 端支持两种 client 模式
- 配置里有 `clientId` 则用预注册 client。
- 否则走动态注册并持久化 `clientInfo`。

2. token/client/state 都落 McpAuth
- `saveTokens/saveClientInformation/saveCodeVerifier/saveState` 都写入 auth store。

3. 回调服务有 state 强校验
- callback 没有 `state` 或 state 不在 pending map 直接拒绝，明确标记潜在 CSRF。

4. pending 管理含超时与反向索引
- `pendingAuths: state -> promise`
- `mcpNameToState` 反向索引支持按 mcpName 取消。
- 超时默认 5 分钟。

5. 回调服务支持单实例复用
- 端口已占用时认为已有实例在跑，不重复起服务。

## implication 是什么 (Harness Implication)
- state 校验是硬要求，不可省略；省略即 OAuth 漏洞。
- 反向索引让“按服务器取消授权”成为可能，提升控制面可用性。
- 本地 callback server 是 IDE/CLI 无缝 OAuth 的关键基础设施，可复用到其他协议接入。
