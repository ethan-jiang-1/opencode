# 4.11 `edit.ts`：多策略替换引擎而非朴素字符串替换

## 源码是什么 (Source)
- `packages/opencode/src/tool/edit.ts`
- 关键符号：
  - `EditTool.execute(...)`
  - `replace(content, oldString, newString, replaceAll?)`
  - 一组 replacer：`Simple/LineTrimmed/BlockAnchor/.../ContextAware`
  - `trimDiff(...)`

## 解读是什么 (Interpretation)
`edit` 的核心创新不是写文件，而是“匹配鲁棒性”：

1. 写入前后都有工程护栏
- `FileTime.withLock/assert` 防并发与陈旧写。
- `ctx.ask(permission=edit)` 带 diff。
- 写后 `Format.file` + `LSP.diagnostics` 反馈。

2. 匹配策略是级联回退
- 从最严格到最宽松：
  - 精确匹配
  - 行级 trim
  - block anchor + 相似度
  - whitespace/indent/escape 归一
  - trimmed boundary
  - context-aware
  - multi-occurrence

3. BlockAnchor 有明确阈值策略
- 单候选阈值更宽。
- 多候选阈值更高，避免误替换。

4. 替换结果的歧义策略
- 找不到：报“精确上下文不足”。
- 找到多个：报“上下文不够唯一”。

5. `trimDiff` 会裁掉公共缩进
- 让 diff 更短、更稳，更适合权限弹窗与模型回看。

## implication 是什么 (Harness Implication)
- 高质量 edit 工具应当把“匹配容错”做成算法层，而不是让模型反复重试改 prompt。
- 若你要扩展到结构化语言（SQL/DSL），可继续在 replacer 链新增语法感知匹配器。
- `edit` 的错误文案本身就是控制器信号，能直接引导模型补充上下文而非盲改。
