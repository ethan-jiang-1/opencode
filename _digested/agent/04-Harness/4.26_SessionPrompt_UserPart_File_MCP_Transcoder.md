# 4.26 `createUserMessage`：File/MCP 输入转码器

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- 关键符号：
  - `createUserMessage(...)`
  - `resolvePart(part)`
  - `mcp.readResource(clientName, uri)`
  - 内嵌 `ReadTool.execute(...)` 调用
  - `decodeDataUrl(...)`

## 解读是什么 (Interpretation)
用户输入 part 在落盘前会被标准化为“可回放消息片段”。

1. `file` part 会按来源类型分流
- `source.type=resource`：走 MCP `readResource`，把 text/blob 转成消息内容与附件。
- `data:` URL：可直接解码为文本或文件附件。
- `file:` URL：按 MIME 决定读取策略。

2. 文本文件不是直接读磁盘，而是复用 ReadTool
- 会合成一条 synthetic 文本：`Called the Read tool with ...`。
- 再把 read 输出或附件作为后续 part，保持行为可审计。

3. 目录也通过 ReadTool 统一输出
- 保证目录浏览格式和常规 read 工具一致。

4. 非文本文件会写入 file part（base64 data URL）
- 同时调用 `FileTime.read` 记录读快照，为后续写入保护服务。

5. `agent` part 会降级成 task 指令提示
- 注入 synthetic 提示文本，指导后续调用 `task` 工具并使用该 subagent。

## implication 是什么 (Harness Implication)
- 这是“输入转码层”，把用户附件转成可追溯的统一会话语义，而不是旁路数据。
- 通过复用 ReadTool，前端上传文件与模型主动 read 获得同构输出格式。
- 若扩展新 part 类型，建议在 `resolvePart` 做单点转码，避免跨层分叉行为。
