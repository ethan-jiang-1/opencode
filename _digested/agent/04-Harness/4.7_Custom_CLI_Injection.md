# 4.7 外部 CLI 注入与原装 Function Call 剥离术 (Custom Tools)

我们在 4.6 讲到，普通的 `bash` 工具就是大模型去**瞎猜试探**命令行，极具不可控性。
如果公司刚刚买了一个新的自动化发版工具叫 `k8s-rocket CLI`，你想通过它把发版能力注给大模型。
你该怎么插进去？

> **极其痛苦的原生路线**：你手动写 OpenAI 的 "Function Call (API 协议)", 自己写个 JSON 丢给大模型。大模型回复你一个 JSON 文本，你自己在代码底层写个极其臃肿的 `switch-case` 解析，一旦模型拼错字段，你的代码当场 Crash 引发惨案。

在 OpenCode 中，它用极其精绝的金字塔结构，不仅剥离了所有脏活累活，还彻底完成了能力的**真空吸附挂载**。我们现在像上一节一样，顺着源码画出它完整的全时序生命流转。

## 🔍 代码溯源：它到底神在哪里？

有了上面这张图，你已经彻底看透了 OpenCode 的高维封装，咱们去代码实现里再印证一下，看看到底这层“Harness”是怎么完成的。

### 第一局关键点：引擎为什么能自己吸附外挂？(`registry.ts`)

为了印证图表里的第一阶段，请查看 `packages/opencode/src/tool/registry.ts` 大约 89 行左右：

```typescript
// 物理扫描工作区
const matches = dirs.flatMap((dir) =>
  Glob.scanSync("{tool,tools}/*.{js,ts}", { cwd: dir, absolute: true, dot: true, symlink: true }),
);

for (const match of matches) {
  // 核心机密用 Node.js 的 dynamic import！完全无侵入载入你写的脚本。
  const mod = yield* Effect.promise(() => import(match));
  for (const [id, def] of Object.entries<ToolDefinition>(mod)) {
      // 通过 fromPlugin 神来之笔，把你的代码“伪装”成了内置的 Function 调用
      custom.push(fromPlugin(id === "default" ? namespace : `${namespace}_${id}`, def));
  }
}
```
这意味着：让一个死掉的 Function Call 复活为你随时想挂就挂、不想挂就删的动态沙箱环境，系统层已经全部打通了。

### 第二局关键点：比 Function Call 强在哪？(`tool.ts`)

在原生 Function Call 下，如果大模型的 JSON 生成出错，你的程序立刻当机（TypeError）。
为了看 OpenCode 怎么封锁这个问题，请查阅 `packages/opencode/src/tool/tool.ts` 源码大约第 62 行：

```typescript
try {
  // Zod 关卡：死死拿捏住大模型的嘴，不老实填参数直接打回去
  toolInfo.parameters.parse(args) 
} catch (error) {
  // 这段精巧的错误抛出，是拯救程序的关键
  throw new Error(
    `The ${id} tool was called with invalid arguments: ${error}.\nPlease rewrite the input so it satisfies the expected schema.`
  )
}
const result = await execute(args, ctx)
```

## 💡 一锤定音：所以你身为架构师到底该干嘛？

看到最后你明白了。
OpenCode 底层的 `registry.ts` 和 `tool.ts` 替你在这中间把脏活累活和所有擦屁股的流程全干完了。

如果你们公司真的引入了 `k8s-rocket`，你**只需要在你的项目底下写死一个极其短小、不超过 30 行的文件 `.opencode/tools/rocket.ts`**：

```typescript
import { z } from "zod";
import { execSync } from "child_process";

export const deployNode = {
  // 告诉模型你的存在
  description: "Use this exclusively to trigger k8s-rocket deployment for a specific node.",
  
  // 被 tool.ts 疯狂保护的入口结构
  parameters: z.object({
    nodeName: z.string().describe("The specific target node name, eg: 'worker-node-1'")
  }),

  // 这里真正执行那款【新软件 CLI】
  execute: async (args, ctx) => {
    // 到了这里，参数 100% 安全，因为上面过了 tool.ts 的 Zod 盘问
    const output = execSync(`k8s-rocket deploy ${args.nodeName}`).toString();
    return { title: "K8s Rocket Execution", output };
  }
};
```

就是通过这么短的一层薄薄的胶水，外设 CLI 像附身怪物一样，钻进了系统的最深层神经节点。这也完全解释清楚了：**外置 CLI 注入系统最顶级的做法，就是把它 Zod 化后，让底层自行拦截调用**。
