# 4.7 自定义 CLI 注入：从外部工具到 Agent 原生能力

## 源码是什么 (Source)
- `packages/opencode/src/tool/registry.ts`
- `packages/opencode/src/tool/tool.ts`
- 协同源码：
  - `packages/opencode/src/session/prompt.ts`（`resolveTools`）

> 内部桥接实现请看 [4.29_SessionPrompt_ResolveTools_Context_Bridge.md](./4.29_SessionPrompt_ResolveTools_Context_Bridge.md)。

## 解读是什么 (Interpretation)
本篇聚焦“如何把公司 CLI 无侵入接入 Agent”。

1. 外部工具通过目录扫描自动加载
- `registry.ts` 会扫描 `tool/tools` 目录并动态 import。
- 导出对象会被包装成统一 Tool 定义并进入注册表。

2. 参数约束与错误回传由工具内核兜底
- `tool.ts` 在执行前先做 schema 校验。
- 参数不合法时返回结构化错误，驱动模型重写 tool input。

3. 调用后自动进入主循环闭环
- 工具结果会以 tool result part 回注会话。
- 模型基于结果进入下一轮决策（继续调工具或结束回答）。

## implication 是什么 (Harness Implication)
- 实践上，最优接入策略是“把 CLI 做成 schema 化工具”，而不是让模型直接拼 bash。
- 这样可复用权限、审计、截断、重试、UI 可观测等既有能力。
- 对企业工具链而言，这是一条低侵入、高约束、可治理的扩展路径。
