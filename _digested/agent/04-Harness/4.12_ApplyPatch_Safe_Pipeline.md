# 4.12 `apply_patch` 安全管线：验证、授权、执行、回显四段式

## 源码是什么 (Source)
- `packages/opencode/src/tool/apply_patch.ts`
- 关键符号：
  - `Patch.parsePatch(...)`
  - `Patch.deriveNewContentsFromChunks(...)`
  - `ctx.ask(permission=edit, metadata.files/diff)`
  - file change apply + `Format` + `LSP`

## 解读是什么 (Interpretation)
`apply_patch` 是一个“先验验证器”，并非直接套 patch：

1. 输入验证
- 空 patch、无 hunk、语法错误都会在执行前拒绝。

2. 预演阶段
- 对每个 hunk 先算出 `oldContent/newContent/diff/additions/deletions`。
- update 走 `deriveNewContentsFromChunks`，先验证可应用性。

3. 路径与权限
- 每个目标文件都过 `assertExternalDirectory`。
- 汇总 `files` 与 `totalDiff` 后一次性 ask `edit` 权限。

4. 执行阶段
- add/update/move/delete 分支执行。
- move 会写新文件后删旧文件，附带 watcher 事件。

5. 执行后诊断
- 触发 `Format.file`、`LSP.touchFile`、`LSP.diagnostics`。
- 输出中附 changed files 摘要和错误诊断。

## implication 是什么 (Harness Implication)
- 把 patch 当“事务草案”先预演，是减少半成功状态的关键。
- UI 若要做可解释审批，`metadata.files` 提供了天然的 per-file 审计数据。
- 对于高风险仓库，完全可以在 ask 前追加自定义策略（敏感路径、diff 大小、删除比例阈值）。
