# 4.2 静态能力注入：Skill 机制 (Static Injection)

在 OpenCode 中，最轻量级且极具性价比的知识注入方式是 **Skill**。它不需要你写复杂的 TypeScript 代码，也不需要启动任何服务，仅仅依靠 Markdown 配置就能为 Agent 挂载静态的业务逻辑。

## 🔬 OpenCode 是怎么做的？

在底层 `prompt.ts` 的 `System Assembly`（系统组装）阶段，引擎会去读取当前的生效 Skills：
```typescript
// 伪代码解析
const skills = yield* SystemPrompt.skills(agent);
const system = [...env, ...(skills ? [skills] : []), ...instructions];
```

OpenCode 原生设计了一个读取机制：它会扫描当前工作区 `.opencode/skills/` 目录下的 Markdown 或 YAML 文件，并在发送给大模型前，将其统统塞进 System Prompt 的底部。这相当于给大模型临时发放了“工作守则”。

## 💡 实战案例：前端规范 Skill

假设你们团队禁止使用原生的 `console.log`，而要求必须使用公司封装的 `@/utils/logger.ts`。如果我们不告诉大模型，它哪怕写代码再厉害，也会频频触犯底线。

你可以创建一个文件：`.opencode/skills/frontend_logger.md`，内容如下：

```markdown
---
name: Frontend Logger Protocol
description: Enforces the use of company standard logger utility.
---

# 内部前端日志打印规范

在本项目中，**严禁**使用原生的 `console.log`, `console.warn`, 或 `console.error`。

如果你需要在此次任务中注入日志，请务必执行以下步骤：
1. 在文件顶部引入: `import { logger } from "@/utils/logger";`
2. 替换所有打印操作，例如：
   ❌ 错误: `console.log("user data", user)`
   ✅ 正确: `logger.info("user data", { user })`

当你进行代码审查 (Review) 时，如果发现原有代码包含 `console.log`，请将其一并重构。
```

### 底层生效逻辑
大模型本身并不知道这个 skill 文件的存在。但在启动 `build` 或 `plan` 相关的请求时，OpenCode 底层 `SystemPrompt.skills` 会将其作为一段 `TextPart` 强插到上下文头部。大语言模型（如 Claude 或 OpenAI）在接收指令时，由于这行“严禁”被前置放置，它在生成 `tool-calls` (比如准备调用 `WriteFile` 覆写文件) 时，就会自动按照规范修改代码。

**一句话总结**：Skill 是给 Agent 快速“灌装”本地纪律的最优解。
