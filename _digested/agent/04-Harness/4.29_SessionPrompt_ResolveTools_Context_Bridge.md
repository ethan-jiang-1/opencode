# 4.29 `resolveTools`：统一工具上下文桥与 Hook 编排点

> 收敛说明：本篇偏内部实现机制。外部 CLI 注入叙事请看 [4.7_Custom_CLI_Injection.md](./4.7_Custom_CLI_Injection.md)。

## 源码是什么 (Source)
- `packages/opencode/src/session/prompt.ts`
- 协同源码：
  - `packages/opencode/src/tool/registry.ts`
  - `packages/opencode/src/provider/transform.ts`
- 关键符号：
  - `resolveTools(...)`
  - 内部 `context(args, options): Tool.Context`
  - `registry.tools(...)` + `ProviderTransform.schema(...)`
  - `plugin.trigger("tool.execute.before/after", ...)`
  - MCP tool 包装：`mcp.tools()` + `truncate.output(...)`

## 解读是什么 (Interpretation)
`resolveTools` 是“AI SDK Tool 协议”与“OpenCode 工具体系”的桥接器。

1. 先构造统一 `Tool.Context`
- 统一注入 `sessionID/messageID/callID/abort/messages`。
- `metadata()` 会回写正在运行的 tool part（title/metadata/status/input/time）。
- `ask()` 会自动 merge agent/session permission 并走 Permission 服务。

2. 内建与自定义工具统一注册
- 从 `registry.tools(...)` 取可用工具。
- 参数 schema 先做 `ProviderTransform.schema`，再包装成 `jsonSchema(...)`。

3. 执行前后有稳定 hook 位
- 每次工具执行都会触发 `tool.execute.before` 与 `tool.execute.after`。
- 扩展逻辑（审计、计费、策略）可以不侵入工具实现本体。

4. MCP 工具有专门适配层
- 把 MCP `content`（text/image/resource）转成 OpenCode `output + attachments`。
- 文本输出经过 `truncate.output`，并回写 `truncated/outputPath` 元数据。

## implication 是什么 (Harness Implication)
- 新工具体系要接入时，优先接到 `resolveTools`，而不是直接拼接到模型请求层。
- `context.metadata` 提供了“运行中可观测”能力，是实时 UI 反馈的关键。
- 这层统一了权限、hook、schema、附件转换，避免每个工具重复造轮子。
