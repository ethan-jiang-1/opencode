# 4.32 ModelsDev 目录层：多级回退与热刷新模型源

## 源码是什么 (Source)
- `packages/opencode/src/provider/models.ts`
- 协同源码：
  - `packages/opencode/src/provider/provider.ts`（`fromModelsDevModel/fromModelsDevProvider`）
- 关键符号：
  - `ModelsDev.Data` lazy 加载链
  - 回退顺序：`OPENCODE_MODELS_PATH/cache models.json -> models-snapshot.js -> 远端 api.json`
  - `ModelsDev.refresh()` + `Data.reset()`
  - 进程级定时刷新（hourly）

## 解读是什么 (Interpretation)
ModelsDev 是 provider/model 元数据的“外部目录注入层”。

1. 模型源有明确回退层级
- 优先读本地文件（可定制路径）。
- 本地不存在时读构建时 snapshot。
- 仍无数据且未禁网时，再 fetch `models.dev/api.json`。

2. 刷新与读取分离
- `Data` 是 lazy 缓存读取；`refresh()` 会拉远端并写缓存文件，再 `Data.reset()` 触发下次重载。

3. Provider 层会把目录数据映射为运行时能力
- `fromModelsDevModel` 把 cost/limit/modalities/tool_call/reasoning/interleaved 映射到内部 `Provider.Model`。
- 并基于 `ProviderTransform.variants(...)` 生成可用推理强度变体。

4. 自动刷新是后台行为
- 非 completions 场景下，启动时刷新一次，之后每小时刷新。

## implication 是什么 (Harness Implication)
- 这层让模型清单变成“可热更新配置”，无需每次发版才能更新模型元数据。
- 企业内网可通过 `OPENCODE_MODELS_PATH/URL` 接管目录源，实现私有模型治理。
- 目录数据和运行时映射分离，方便做审计（数据来源）与执行（能力映射）解耦。
