# 4.4 被外部系统驾驭：ACP (Agent Client Protocol)

MCP (上一节) 是怎么让 Agent 读取外部知识的协议。
而 **ACP (Agent Client Protocol)** 则是**外部系统如何操控、驾驭我们这个 Agent 的协议**。

你可以去 `packages/opencode/src/acp/README.md` 和 `packages/opencode/src/acp/agent.ts` 中窥探这部分设计。这解答了一个重要问题：**如果公司的重型客户端（如桌面 IDE Zed）希望把 OpenCode 当做“内置 AI”使用，该怎么通讯？**

## 🔬 OpenCode 是怎么做的？

OpenCode 提供了一套清洁的、协议合规的 ACP 实现：
- 它实现了 `@agentclientprotocol/sdk` 中的 `Agent` 接口。
- 利用基于 JSON-RPC (标准的输入/输出流协议)，允许外部系统像使用本地库一样操纵大模型。
- `acp/agent.ts` 将外部传来的 ACP 会话 `session/prompt` 对齐、映射到了 OpenCode 自己内部核心的 `SessionPrompt.prompt()` 流转图中。

```typescript
// ACP 的映射 (Mapping) 本质
ACP session/new → 调用内部 Session 构建逻辑
ACP session/prompt → 调用内部 SessionPrompt.prompt()，进而走入上几章讲过的 runLoop
```

## 💡 实战案例：让 Zed IDE 驱动 OpenCode

当开发者在外部文本编辑器 Zed 里编写代码，并不想跳出去打开终端使用 OpenCode CLI 时可以这么做。

如果你看源码里的案例，仅仅需要在 Zed 配置文件中加一段内容：
```json
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

这时候发生了什么？
1. Zed 编辑器会在后台悄悄执行 `opencode acp` 命令，这把 OpenCode 作为后端 Daemon 服务唤醒拉起。
2. Zed 编辑器会充当 **客户端 (ACP Client)**，而 OpenCode 系统充当 **服务端 (ACP Agent Server)**。
3. 用户在编辑器左侧选中的文件、高亮代码甚至编译报错，全都被 Zed 通过 `session/prompt` 标准协议塞装进 JSON 报文里，通过 Stdout/Stdin 发给 OpenCode 核心层。
4. OpenCode 的大模型在底层算完，直接推回调指令：修改某某文件。Zed 编辑器负责接手这个 UI 交互进行刷新。

**核心意义**：
有了 ACP，OpenCode 就从一个单纯的命令行工具，蜕变成了一个可以提供企业级集成 (Integration)能力的**无头核心 (Headless AI Core)**，这让将 AI 赋能各种重型生产体系变得极为简单。
