# 4.4 ACP：OpenCode 与外部客户端的协议面

## 源码是什么 (Source)
- `packages/opencode/src/acp/agent.ts`
- 协同源码：
  - `packages/opencode/src/acp/session.ts`
  - `packages/opencode/src/session/message-v2.ts`
- 关键符号：
  - `ACP.Agent`（`initialize/newSession/loadSession/prompt`）
  - `runEventSubscription()/handleEvent(...)`
  - `requestPermission -> sdk.permission.reply`
  - `connection.sessionUpdate(...)`

## 解读是什么 (Interpretation)
ACP 适配器的核心是“协议翻译”，不是再实现一套 agent runtime。

1. 会话控制面
- `new/load/resume/fork` 都通过 SDK 调用原生 session 服务。
- `ACPSessionManager` 维护 ACP 侧状态（cwd、model、mode、variant）。

2. 事件翻译面
- 订阅全局事件流，把内部 `message.part.* / permission.*` 翻译成 ACP `sessionUpdate`。
- 细分推送 `tool_call_update`、`agent_message_chunk`、`agent_thought_chunk`、`plan` 等。

3. 权限桥接面
- 内部 `permission.asked` 会转成 ACP `requestPermission`。
- 用户在 IDE/客户端选择后，再回写 `sdk.permission.reply`，完成执行闸门闭环。

4. 输入输出转码面
- ACP prompt 内容（text/image/resource）会映射为 OpenCode parts。
- 历史回放时反向映射为 ACP chunk/tool updates。

## implication 是什么 (Harness Implication)
- 任何实现 ACP 的前端都可复用同一套 OpenCode 引擎，不必重复实现工具链。
- 协议层与运行时分离后，UI 可快速迭代，核心逻辑保持单点可信。
- 事件映射正确性决定“远端体验是否实时可信”，是 ACP 适配质量关键。
