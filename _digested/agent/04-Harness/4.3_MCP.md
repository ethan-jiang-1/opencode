# 4.3 MCP：外部能力与外部资源桥接层

## 源码是什么 (Source)
- `packages/opencode/src/mcp/index.ts`
- 协同源码：
  - `packages/opencode/src/session/prompt.ts`
- 关键符号：
  - `MCP.tools()/prompts()/resources()`
  - `connectRemote/connectLocal`
  - `readResource(clientName, resourceUri)`
  - `startAuth/authenticate/finishAuth`

## 解读是什么 (Interpretation)
MCP 在 OpenCode 里有两条通路：工具通路和资源通路。

1. 工具通路
- MCP server 的 `listTools` 被转换成 AI SDK `dynamicTool`。
- 在 `resolveTools` 中并入本地工具集合，并走统一 permission/hook/truncate 流程。

2. 资源通路
- 用户输入 part 带 `source.type === "resource"` 时，`prompt.ts` 会调用 `mcp.readResource`。
- 读取结果转成 synthetic text/file part 注入会话，不需要模型自己写网络访问逻辑。

3. 连接与鉴权通路
- 支持本地 `stdio` 和远端 `StreamableHTTP/SSE`。
- 远端支持 OAuth，状态机包含 `connected/needs_auth/needs_client_registration/failed`。

## implication 是什么 (Harness Implication)
- MCP 让“模型推理”与“企业资源访问”解耦，便于治理与审计。
- 高噪声外部返回必须依赖统一截断策略，避免上下文污染。
- 鉴权复杂度被收敛在 MCP 层，客户端与 agent 逻辑可保持干净。
