# 4.1 Interceptor Hooks：运行时拦截与注入面

## 源码是什么 (Source)
- `packages/opencode/src/plugin/index.ts`
- 协同源码：
  - `packages/opencode/src/session/prompt.ts`
  - `packages/opencode/src/session/llm.ts`
- 关键符号：
  - `Plugin.trigger(...)`
  - `experimental.chat.messages.transform`
  - `experimental.chat.system.transform`
  - `tool.execute.before/after`
  - `command.execute.before`

## 解读是什么 (Interpretation)
Hook 系统把“扩展行为”放在主干执行链上，而不是外挂脚本。

1. Hook 执行是顺序且确定的
- `Plugin.trigger` 按加载顺序逐个调用 hook。
- 这保证多插件并存时行为可预测。

2. 拦截点覆盖主要生命周期
- prompt 侧：消息改写、命令执行前改写。
- llm 侧：system prompt 变换、chat 参数与 headers 注入。
- tool 侧：执行前后可审计与改写输出。

3. 输出对象是可变引用
- hook 接收 `(input, output)`，可直接修改 output 内容再传递。
- 这使 RAG 注入、策略过滤、审计标签可无侵入接入。

## implication 是什么 (Harness Implication)
- 企业策略、私有上下文、审计逻辑应优先落在 hook，而不是写死在 agent prompt。
- Hook 要求幂等和低延迟；否则每轮推理都会被放大拖慢。
- 对一致性敏感场景，必须关注插件加载顺序与冲突策略。
