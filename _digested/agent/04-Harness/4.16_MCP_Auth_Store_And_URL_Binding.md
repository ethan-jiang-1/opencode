# 4.16 MCP Auth Store：凭证存储与服务 URL 绑定

## 源码是什么 (Source)
- `packages/opencode/src/mcp/auth.ts`
- 关键符号：
  - `Entry { tokens, clientInfo, codeVerifier, oauthState, serverUrl }`
  - `getForUrl(mcpName, serverUrl)`
  - `update* / clear*` 字段级更新器
  - 文件：`Global.Path.data/mcp-auth.json`（权限 0600）

## 解读是什么 (Interpretation)
MCP 认证数据是一个独立的键值仓，而不是散落配置：

1. 结构化存储
- token、动态注册 client、PKCE code verifier、oauth state 分字段管理。

2. URL 绑定保护
- `getForUrl` 要求 entry.serverUrl 与当前 serverUrl 一致才返回。
- 防止“同 mcpName 指向新服务器”时误用旧凭证。

3. 字段更新模板化
- `updateField/clearField` 统一生成更新函数，避免重复样板。

4. token 过期判断内建
- `isTokenExpired` 以 Unix 秒比较 `expiresAt`。

## implication 是什么 (Harness Implication)
- URL 绑定是多环境安全边界，必须保留；否则 dev/prod 切换易串凭证。
- 把 auth 存储独立为 service，使 OAuth 流程可测试、可替换。
- 0600 文件权限是基础防线，部署时应确保 data 目录权限策略一致。
