# 4.8 Plugin 运行时：Hook 顺序、兼容层与事件注入

## 源码是什么 (Source)
- `packages/opencode/src/plugin/index.ts`
- 关键符号：
  - `Plugin.layer`
  - `applyPlugin(...)`
  - `Plugin.trigger(name, input, output)`
  - `getLegacyPlugins(...)`

## 解读是什么 (Interpretation)
这层是 OpenCode 的“插件执行内核”，核心是顺序确定性：

1. 内建 + 外部插件并存
- 内建插件：`CodexAuth/CopilotAuth/GitlabAuth/PoeAuth`。
- 外部插件来自 config，经过 plan/resolve/load 生命周期。

2. 同时兼容 V1 模块与 legacy 导出
- 优先走 `readV1Plugin(..., "server")`。
- 否则扫描 legacy 导出并抽取 server 函数。

3. 外部插件加载是串行执行
- 明确注释：为确保 hook 注册与执行顺序可预测，保持 sequential。

4. trigger 语义是“按顺序原地改 output”
- `trigger(name, input, output)` 依次调用所有 hook。
- 返回的是同一个被逐步变形的 `output` 对象。

5. 事件总线桥接
- `bus.subscribeAll()` 会把系统事件转发到 hook 的 `event` 回调。

## implication 是什么 (Harness Implication)
- 插件顺序就是行为语义；两个插件改同一 output 字段时，后者天然覆盖前者。
- 做企业插件生态时，必须有顺序治理机制（优先级或分层），否则行为不可解释。
- 任何“全局注入”能力都应尽量走 hook，不要在业务代码里散落 if/else。
